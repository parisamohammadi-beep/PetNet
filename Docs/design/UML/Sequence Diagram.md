# Sequence Diagram — پت نت

## ۱. مقدمه

این دیاگرام ترتیب تعاملات بین اجزا را در یک سناریو نشان می‌دهد.

## ۲. سناریو:رزرو نوبت دامپزشکی

### ۲.۱ Actors
- **مشتری – صاحب پت** — کاربر
- **Frontend** — HTML / CSS/ Js
- **Backend** — python / Django
- **Database** — PostgreSQL

### ۲.۲ ترتیب

1. مشتری روی دکمه «رزرو نوبت» در صفحه دامپزشک کلیک می‌کند
2. Frontend درخواست POST به /api/appointments می‌فرستد
3. Backend درخواست را اعتبارسنجی می‌کند
4. Backend وضعیت زمان (TimeSlot) را در Database چک می‌کند که آیا هنوز آزاد است یا نه.
5. Backend نوبت (Appointment) را با وضعیت PENDING ثبت می‌کند و TimeSlot را رزرو شده علامت می‌زند.
6. Backend شماره پیگیری نوبت را برمی‌گرداند.
7. Frontend پیام موفقیت (و ارسال به درگاه پرداخت یا تایید نهایی) را نشان می‌دهد

## ۳. سناریو: ثبت آگهی واگذاری پت

### ۳.۱ Actors
**مشتری – واگذارکننده پت** — کاربر
- **Frontend** – HTML / CSS / JS
- **Backend** – Python / Django
- **Database** – PostgreSQL

### ۳.۲ ترتیب

1. مشتری فرم آگهی واگذاری پت را پر کرده و روی «ثبت آگهی» کلیک می‌کند.
2. Frontend درخواست POST به /api/adoptions می‌فرستد.
3. Backend اعتبارسنجی می‌کند (وجود عکس، اطلاعات پت و توضیحات).
4. Backend آگهی را با وضعیت PENDING_REVIEW (در انتظار تایید) در Database ذخیره می‌کند.
5. Backend پیام موفقیت را برمی‌گرداند.
6. Frontend پیام «آگهی شما ثبت شد و پس از تایید ادمین نمایش داده می‌شود» را نشان می‌دهد.

## ۴. سناریو: ثبت سفارش در پت‌شاپ 

### ۴.۱ Actors
**مشتری – واگذارکننده پت** — کاربر
- **Frontend** – HTML / CSS / JS
- **Backend** – Python / Django
- **Database** – PostgreSQL

### ۴.۲ ترتیب

1. مشتری روی دکمه «ثبت سفارش» در سبد خرید کلیک می‌کند.
2. Frontend درخواست POST به /api/orders می‌فرستد.
3. Backend درخواست را اعتبارسنجی می‌کند.
4. Backend موجودی محصولات (Product Stock) را در Database چک می‌کند.
5. Backend سفارش (Order) و آیتم‌ها (OrderItems) را ثبت می‌کند.
6. Backend موجودی محصولات را کاهش می‌دهد.
7. Backend شماره پیگیری سفارش را برمی‌گرداند.
8. Frontend پیام موفقیت و انتقال به درگاه پرداخت را نشان می‌دهد.
